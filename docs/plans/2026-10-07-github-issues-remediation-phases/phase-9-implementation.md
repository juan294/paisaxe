## Behavior and contracts

The root provider owns one TanStack Query client. Analytics, stories, feature flags, favorites and voice access use that engine behind their existing hook APIs. Query keys include version, domain and public/private scope. Private keys contain verified user identity and an opaque session scope; bearer tokens remain request closures and never enter keys or persistence (`src/lib/client-query.tsx:76`). The installed exact dependency is `@tanstack/react-query@5.104.1`, with MIT license and lockfile verification recorded privately. Current official TanStack documentation and installed public API types were checked before adoption.

Auth changes synchronously select a fresh scope and hide previous private values. The identity effect cancels/removes obsolete queries and purges owned private storage after logout. Unscoped legacy favorites are deleted without reading or uploading them (`src/lib/client-query.tsx:125`, `src/lib/client-query.tsx:140`). Verified per-user favorites persistence has a version, owner, finite timestamp and validated string array. Corrupt or foreign records are discarded; optional storage failures do not prevent network writes (`src/hooks/use-favorites.ts:57`).

Public stories retain the version-1 slim storage format, five-minute query freshness, 24-hour storage limit and existing 30-second storage-bootstrap grace. Optional consumed fields are validated before restoration. Seeds are adopted in effects, never by mutating a singleton during render. Explicit server timestamps order seed replacement; an unknown-age or older seed cannot overwrite a completed shared result. Accepting a newer seed cancels an older in-flight request, preventing its eventual body from overwriting either the shared result or stories persistence. Server observation time does not establish database-version freshness (`src/hooks/use-stories.ts:214`, `src/app/immersive/immersive-data-loader.tsx:27`). Flags retain 60-second freshness, one timed seed revalidation, disabled root-route behavior and dummy-browser fixture behavior (`src/hooks/use-feature-flags.ts:51`). Staggered subscribers compare shared freshness and join an existing read.

Analytics followers subscribe to one result and share errors/retry while retaining permitted stale data. Focus revalidation preserves the actual editing element, focus and value. Public stale failures disclose a localized retry in favorites, immersive, immersive no-results and root pricing (`src/components/cache-retry-notice.tsx:3`).

Favorites record per-story optimistic intents in the Query cache. Independent failed writes roll back only their own story. Same-story network writes serialize through the Query mutation scope while optimistic changes remain immediate. Revision checks cover both optimistic start and settlement, so held response bodies cannot erase completed writes. Each automatic reconciliation is consumed once; failed reads disclose retry instead of looping. Settled mutation observers reset so the Query engine can collect them (`src/hooks/use-favorites.ts:330`).

Voice access shares issuance denial before refreshing, cancels older grants, refreshes after entitlement changes and expires at the actual deadline. Long monthly deadlines rearm within the platform timer limit; multiple subscribers share one expiry read (`src/hooks/use-voice-access.ts:121`). No live payment, model, voice or provider call was made.
