## Proposed budgets for phase review

Every new budget uses the existing 60-second sliding window and distributed production fail-closed implementation. Existing chat 10/minute (unknown IP 3/minute), booking chat 20/minute, voice-session 10/minute, suggestions 1/minute, weather 30/caller and 180/global, places 20/caller and 120/global, make-booking 3/customer/10minutes and atomic DB default 100/day are unchanged. `src/lib/request-rate-limit.ts` is the per-method registry; existing routes retain their established implementation and namespaces, rather than moving them for style.

New proposals: favorites GET 60/minute/user; favorites POST+DELETE share 30/minute/user; suggestions GET 60/minute/user; voice-access GET 60/minute/user; embedded checkout POST 10/minute/user; MCP save-favorite POST 30/minute/IP prefix plus 180/minute globally. Auth rejection precedes all new limits. MCP caller-supplied conversation IDs cannot evade the new global write ceiling.

Derivation: the favorites hook fixture renders the real hook and toggles all 25 catalogue items sequentially, measuring one initial GET and 25 mutations; 30/minute allows that burst plus five immediate corrections. The paid-access fixture renders the real hook and exercises initial resolution plus six explicit refreshes, measuring seven GETs with no polling; 60/minute leaves room for repeated route mounts and post-purchase recovery. Authenticated favorite/suggestion reads use the same non-metered 60/minute read ceiling. The checkout fixture executes the actual client-secret callback for initial load and two retries, measuring three POSTs; 10/minute retains the existing signed-session mint ceiling and room for reloads. Save-favorite writes have the same 30/minute cheap-write ceiling as favorites, with 180/minute global ceiling aligned with existing weather global volume; the latter is an intentional bound on total DB writes even if callers rotate identifiers. These are deterministic synthetic interaction fixtures, not observed production traffic or empirical abuse thresholds. Exact constants require independent phase review before integration.

Public stories and feature-flags reads are exempt: the public response caches for 60 seconds with a 120-second stale window, stories also use a 60-second source cache, and neither invokes a paid provider. MCP save-favorite/make-booking GET documentation is constant and performs no I/O. POST make-booking/status is a constant no-I/O acknowledgement and does not change booking state. The registry explicitly records each exemption. This work introduces no voice-minute cap; the accepted minutes policy remains deferred.
