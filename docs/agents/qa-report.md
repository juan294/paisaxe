## Root Cause Analysis

### Primary: CSRF Token Validation Blocking QA Tests (ALL 12 failures)

**What changed:** CSRF protection was added to `src/proxy.ts` after the QA tests were written. The `handleCsrfValidation()` function (proxy.ts:430-449) now requires:

1. A `__csrf` cookie (set by the proxy on non-API page loads)
2. A matching `x-csrf-token` request header
3. Both must match via `timingSafeEqual()`

**Why tests fail:** The QA test (`src/tests/qa/llm-quality.test.ts:27-31`) makes bare `fetch()` calls:
```typescript
const response = await fetch(`${API_URL}/api/chat`, {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ message }),
});
```

This request has no `__csrf` cookie and no `x-csrf-token` header, so the proxy returns 403 before the request reaches the chat API.

**CSRF-exempt routes** (defined in `src/lib/csrf.ts`): `/api/webhooks/`, `/api/mcp/`, `/api/cron/`, `/api/health`. The chat endpoint is intentionally NOT exempt — it's a state-changing endpoint used by the browser client.

### Secondary: Health Check Script Staleness

Two of three health checks fail due to outdated expectations in `scripts/qa-agent.sh`:

| Issue | Location | Fix |

| Checks for `"status":"ok"` instead of `"status":"healthy"` | `qa-agent.sh:99` | Change grep pattern to `"status":"healthy"` |
| References deleted `/api/stripe-test` endpoint | `qa-agent.sh:126` | Remove Stripe check or replace with `/api/health` Stripe sub-check |

The test needs to:
1. First make a GET request to any page to receive the `__csrf` cookie
2. Extract the cookie value
3. Include both the cookie and the `x-csrf-token` header in subsequent POST requests

```typescript
// Proposed fix sketch:
async function getCsrfToken(): Promise<{ cookie: string; token: string }> {
  const res = await fetch(`${API_URL}/`);
  const setCookie = res.headers.get('set-cookie') || '';
  const match = setCookie.match(/__csrf=([^;]+)/);
  const token = match?.[1] || '';
  return { cookie: `__csrf=${token}`, token };
}
```
