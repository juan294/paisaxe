**10th consecutive run with this blocker.** No LLM quality data since 2026-02-02. **Over 9 weeks of zero visibility into LLM quality.**

### Root Cause Analysis

The `sendChatMessage()` helper in `llm-quality.test.ts:25-51` sends a plain `fetch()` POST with only `Content-Type: application/json`. The proxy (`src/proxy.ts`) validates CSRF tokens on all non-exempt API routes. `/api/chat` is NOT in the CSRF exempt list (correctly — it's a user-facing endpoint).

The CSRF-exempt prefixes in `src/lib/csrf.ts` are: `/api/webhooks/`, `/api/mcp/`, `/api/cron/`, `/api/health`.

The fix requires the test to either:
- **Option A (recommended):** Perform a GET to the app first to obtain the `__csrf` cookie, then include both the cookie and `x-csrf-token` header in subsequent POST requests
- **Option B:** Add `/api/chat` to `CSRF_EXEMPT_PREFIXES` in `src/lib/csrf.ts` — **NOT recommended** as this weakens production security
- **Option C:** Set a test-only CSRF bypass header for the QA test environment

**Specific fix for Option A:**
```typescript
// In sendChatMessage(), before the POST:
const pageResponse = await fetch(`${API_URL}/immersive`);
const cookies = pageResponse.headers.get('set-cookie');
const csrfToken = parseCsrfFromCookies(cookies);
// Then include in POST headers:
headers: {
  'Content-Type': 'application/json',
  'x-csrf-token': csrfToken,
  'Cookie': `__csrf=${csrfToken}`,
}
```
