### Issue 2: Chat Panel Not Found (Journeys 3, 7, 14) — PERSISTENT (2nd report)

**Root cause confirmed:** The `VoiceChat` component is dynamically imported (`src/app/immersive/immersive-page-content.tsx:22-28`) with `ssr: false` and `loading: () => null`. When `chatOpen` becomes true:
1. Dynamic import triggers (~15KB+ deferred chunk)
2. No loading indicator renders (loading returns `null`)
3. Component must mount, hydrate, and animate (`animate-in slide-in-from-bottom-4 duration-300`)

The E2E test's default 5-second timeout is insufficient. The chat panel root element at `voice-chat.tsx:161` uses `className="fixed inset-0 z-50 ..."` with **no `data-testid`**, making the selector fragile.

**Element confirmed present in source** — this is a timing issue, not a missing component.

### Issue 3: Localization Regression (Journey 1) — NEW

**Test assertion (`qa-journey.spec.ts:85`):**
```
Expected: "Playa del Silencio"
Received: "Beach of Silence"
```

The test captures `firstTitle` ("Playa del Silencio" in Spanish), navigates right, then left, and expects to return to the same title. Instead it receives "Beach of Silence" (English).

**Root cause hypothesis:** The story title switches languages during navigation. This indicates:
- **Localization race condition:** Story translations may load asynchronously. The initial render shows Spanish (based on `lang="es"` in the HTML), but after navigating away and back, the English translation loads first.
- **ISR/caching interaction:** The recent ISR enablement for `/immersive` (commit `dbcd6c5`) may serve cached English translations on subsequent renders.
- **Feature flag mock does not mock story data** — stories come from the server/SSR with potential locale-dependent content.

### Issue 4: Info Panel Toggle Broken (Journey 5) — NEW

**Test assertion (`qa-journey.spec.ts:190`):**
```
Expected: opacity "0"
Received: opacity "1"
```

After pressing 'i', the bottom panel (`.absolute.bottom-0.left-0.right-0`, also has `data-testid="story-info-panel"`) should transition to `opacity-0`. The component uses `showInfo` state toggled by the 'i' key (`story-viewer.tsx:159-160`), with CSS classes `opacity-100 translate-y-0` (visible) and `opacity-0 translate-y-8` (hidden) with `duration-500` transition.

**Root cause hypothesis:**
- The 'i' key handler may have been affected by recent refactoring or focus management changes
- The `waitForTimeout(600)` after key press should be sufficient for the 500ms transition, but keyboard events may not be reaching the handler if focus is on a different element
- The PPR/ISR changes (commits `0c13c00`, `dbcd6c5`) may affect hydration timing, causing the event handler to not be attached when 'i' is pressed

let csrfCache: { cookie: string; token: string } | null = null;

async function getCsrfToken(): Promise<{ cookie: string; token: string }> {
  if (csrfCache) return csrfCache;
  const res = await fetch(`${API_URL}/`);
  const setCookie = res.headers.get('set-cookie') || '';
  const match = setCookie.match(/__csrf=([^;]+)/);
  const token = match?.[1] || '';
  csrfCache = { cookie: `__csrf=${token}`, token };
  return csrfCache;
}

async function sendChatMessage(message: string, retries = 3): Promise<ChatResponse> {
  const csrf = await getCsrfToken();
  for (let attempt = 1; attempt <= retries; attempt++) {
    const response = await fetch(`${API_URL}/api/chat`, {
      method: 'POST',
      headers: {
        'Content-Type': 'application/json',
        'Cookie': csrf.cookie,
        'x-csrf-token': csrf.token,
      },
      body: JSON.stringify({ message }),
    });
    // ... rest of retry logic
  }
}
