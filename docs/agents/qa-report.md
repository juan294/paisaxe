## Root Cause Analysis

### Issue 1: CSRF Token Blocking LLM Tests (ALL 12 failures) — PERSISTENT

**Status: Unfixed since 2026-02-15 (3 consecutive reports)**

Same root cause as the previous two reports. The `sendChatMessage()` function in `src/tests/qa/llm-quality.test.ts:25-31` makes bare `fetch()` calls without CSRF tokens. The proxy (`src/proxy.ts:462-481`) returns 403.

**Fix required:** Add CSRF token acquisition to the test helper (see Priority 1 recommendation below).

### Issue 2: Chat Panel Selector Stale (Journeys 3, 7, 14) — NEW

**Root cause:** The E2E tests locate the chat panel using `page.locator('.fixed.inset-0.z-50')` (e.g., `qa-journey.spec.ts:121`). The `VoiceChat` component in `src/components/immersive/voice-chat.tsx:141` still uses `className="fixed inset-0 z-50 ..."`, so the class itself hasn't changed.

**Most likely cause:** The `VoiceChat` component is **dynamically imported** (`src/app/immersive/immersive-page-content.tsx:22-28`) and wrapped in `Suspense`. When the ask button is clicked, it sets `chatOpen = true`, which triggers the dynamic import. The 5-second timeout in the E2E test may not be sufficient for:
1. Dynamic import resolution
2. Component hydration
3. Animation rendering

The component is only rendered when `chatOpen` is true (line 221-232 of `immersive-page-content.tsx`), and the dynamic import loading state returns `null`. The test clicks `[data-testid="ask-button"]` and immediately expects the panel to be visible within 5000ms, but the dynamic import + Suspense may delay rendering beyond this window.

**Alternative hypothesis:** A CSS change or parent layout change may cause the element to exist in the DOM but not be considered "visible" by Playwright. The error says "element(s) not found", confirming the element isn't rendered at all within the timeout.

### Issue 3: Story Ordering Mismatch (Journey 2) — NEW

**Test assertion (`qa-journey.spec.ts:108`):**
```
Expected: "Cachopo Asturiano"
Received: "Basilica of Covadonga"
```

The test navigates right (ArrowRight), then left (ArrowLeft), expecting to return to the first story. Instead it lands on a different story. Possible causes:
- **Story order changed** in the fallback data or DB query
- **Keyboard navigation wraps** at boundaries differently than expected
- **Race condition:** The 500ms `waitForTimeout` may not be enough for the navigation animation/state update

Update `sendChatMessage()` in `src/tests/qa/llm-quality.test.ts` to acquire CSRF tokens before making API calls:

```typescript
let csrfCache: { cookie: string; token: string } | null = null;

async function getCsrfToken(): Promise<{ cookie: string; token: string }> {
  if (csrfCache) return csrfCache;
  const res = await fetch(`${API_URL}/`);
  const setCookie = res.headers.get('set-cookie') || '';
  const match = setCookie.match(/__csrf=([^;]+)/);
  const token = match?.[1] || '';
  csrfCache = { cookie: `__csrf=${token}`, token };
  return csrfCache;
}

async function sendChatMessage(message: string, retries = 3): Promise<ChatResponse> {
  const csrf = await getCsrfToken();
  for (let attempt = 1; attempt <= retries; attempt++) {
    const response = await fetch(`${API_URL}/api/chat`, {
      method: 'POST',
      headers: {
        'Content-Type': 'application/json',
        'Cookie': csrf.cookie,
        'x-csrf-token': csrf.token,
      },
      body: JSON.stringify({ message }),
    });
    // ... rest of retry logic
  }
}
```
